# Notes for coding agents

Read `/CONTRIBUTING.md` first: its guidelines (coding standards,
implementation practices, pull-request checklist) apply to agents as well. The
notes below only add what is specific to working as an agent in this
repository.

## Dependencies

- Do not edit files under `/deps` unless to patch a dependency, using a new
  branch. Each directory there is a git submodule of
  another repository; changes go to that repository first, and then both the
  submodule and its pin in `/alire.toml` are moved to the new commit (they must
  match, see `scripts/verify-pins.sh`).
- `/deps/_configs` holds configuration files generated by `alr` for
  dependencies that do not commit their own. Regenerate them with `alr` rather
  than editing them by hand.

## Generated sources

- `/src/templates` is generated from `/templates` by
  `support/embedder/embedder.sh`. Do not edit it directly; run the script after
  changing a template. CI checks that both are in sync.

## Testing

- The full Python testsuite takes several minutes. While iterating, run only
  the relevant tests, e.g. `cd testsuite && ./run.py -E tests/index`, and run
  the full suite before handing over a change.
- Without network access, define `ALIRE_TESTSUITE_DISABLE_NETWORK_TESTS` so
  that tests needing it are skipped instead of failing. Similarly,
  `ALIRE_TESTSUITE_DISABLE_DOCKER` skips tests that need Docker.
- Tests run twice by default, once with sandboxed and once with shared builds
  (see the `build_mode` key in `test.yaml` and `/testsuite/README.md`).
